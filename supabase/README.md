# 🛡️ خطة الحماية والأمان لقاعدة بيانات متجر خُضرة (Supabase SQL Editor)

تم إعداد ملف الـ SQL المرفق (`supabase/01_security_hardening.sql`) لحماية متجر خُضرة من:
1. **الطلبات المتكررة (Duplicate Orders)** عند الضغط المزدوج على زر التأكيد أو تكرار المحاولة.
2. **الطلبات المزيفة والسبام (Fake / Spam Orders)** عبر فحص أرقام الهواتف المغربية ومنع الروبوتات.
3. **تجاوز المعدل (Rate Limiting)** بحد أقصى 3 طلبات لكل مستخدم في الساعة الواحدة.
4. **فترة تهدئة أمنية (3-Minute Cooldown)** تمنع إرسال طلب ثانٍ لنفس الرقم خلال 3 دقائق.
5. **تتبع بصمة الجهاز والمتصفح وعنوان الـ IP** وكشف الحسابات المتعددة من نفس الجهاز.

---

## 🚀 طريقة التنفيذ في دقيقة واحدة:

1. افتح لوحة تحكم مشروعك في [Supabase Dashboard](https://supabase.com/dashboard).
2. اختر مشروعك الخاص بمتجر **خُضرة**.
3. من القائمة الجانبية على اليسار، اضغط على **SQL Editor** (أيقونة `>_`).
4. اضغط على **+ New Query** لإنشاء صفحة استعلام جديدة.
5. انسخ محتويات الملف:
   ```
   supabase/01_security_hardening.sql
   ```
6. الصق الكود كاملاً في محرر الـ SQL.
7. اضغط على الزر الأخضر **Run** (أو اختصار `Ctrl + Enter` / `Cmd + Enter`).
8. ستظهر رسالة باللون الأخضر: `Success. No rows returned` — وهذا يعني أن كل جداول الأمان والفهارس ومؤشرات الحماية أصبحت نشطة بنسبة 100%!

## 📋 تفاصيل المكونات الأمنية المضمنة في السكريبت:

| المكون | الوظيفة | الآلية |
| :--- | :--- | :--- |
| **Idempotency Key** | منع تكرار الطلب عند الضغط المزدوج | فهرس فريد `UNIQUE INDEX` يرفض أي طلب متطابق بنفس المفتاح |
| **3-Minute Cooldown** | منع نفس الزبون من إرسال طلبات متتالية | Trigger خادم يرفض أي طلب جديد لنفس الرقم قبل مرور 180 ثانية |
| **Rate Limit (3/ساعة)** | حماية المتجر من الإغراق بالطلبات | Trigger خادم يتحقق من عدم تجاوز 3 طلبات خلال 60 دقيقة |
| **Device Fingerprint** | كشف وتتبع الجهاز الرقمي | تسجيل بصمة الجهاز لمنع محاولات التلاعب بالأسماء |
| **Client ID & IP** | التدقيق الجنائي والتتبع | تسجيل معرف العميل وعنوان الـ IP في كل طلب |
| **Security Audit Logs** | سجل المحاولات المحظورة | جدول `order_security_logs` يسجل كل محاولة سبام تلقائياً |
| **Row Level Security (RLS)** | حماية خصوصية بيانات الزبائن | منع الاطلاع العام على الطلبات وحصرها بالإدارة فقط |
| **Suspicious Orders View** | كشف الطلبات المشبوهة للإدارة | عرض مباشر للطلبات القادمة من نفس الجهاز بأرقام مختلفة |

---

## 🧪 التحقق من عمل الحماية:
- **في التطبيق:** بمجرد تقديم طلب تجريبي، ستلاحظ ظهور عداد تنازلي للتهدئة (3 دقائق)، كما سيتعطل زر الإرسال تلقائياً مع إشعار توضيحي.
- **في Supabase:** يمكنك فحص جدول `orders` لرؤية الأعمدة الجديدة (`idempotency_key`, `client_id`, `device_fingerprint`, `ip_address`).
